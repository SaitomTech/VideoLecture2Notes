# macOS版リリース手順

このプロジェクトは現在、macOS Apple Silicon専用です。

リリースは、GitHub画面でタグとReleaseを作成し、GitHub ActionsがそのReleaseにDMGを添付する方式を採用しています。

## 一度だけ必要な設定

リポジトリに次のWorkflowが存在することを確認します。

```text
.github/workflows/release-macos.yml
```

GitHubリポジトリの `Settings > Actions > General` で、GitHub Actions自体が有効になっていることを確認します。

このWorkflowには次の設定が入っています。

```yaml
permissions:
  contents: write
```

そのため、通常の個人リポジトリでは `Workflow permissions` を `Read repository contents and packages permissions` のままでも、このWorkflowが必要な権限を要求できます。Actionsの権限は必要最小限にしています。

ただし、次のケースではリポジトリまたはOrganizationの設定変更が必要です。

- `contents: write` が組織ポリシーによって禁止されている
- GitHub Actionsの実行自体が無効になっている
- Actions permissionsが、Workflowで使用する外部Actionを禁止している

Actionsの実行権限を変更できる場合は、次を確認します。

- `Settings > Actions > General > Actions permissions`：使用するActionが許可されていること
- `Workflow permissions`：失敗ログに403や権限不足が出た場合だけ `Read and write permissions` に変更する
- `Allow GitHub Actions to create and approve pull requests`：このWorkflowには不要

追加のPersonal Access TokenやApple Developer関連のSecretは不要です。`GITHUB_TOKEN`がReleaseへの成果物アップロードに使われます。

## リリース前の準備

### 1. 変更をmainへ反映する

リリースしたい変更がGitHub上の対象ブランチに反映されていることを確認します。

### 2. バージョンを更新する

現在のアプリバージョンは、次のファイルで管理されています。

```text
src-tauri/tauri.conf.json
src-tauri/Cargo.toml
```

両方の `version` を同じ値に更新します。例えば次のリリースが `0.2.0` の場合は、両方を `0.2.0` にします。

`package.json` のバージョンは現在 `0.0.0` のままですが、Tauriの配布物のバージョン判定には `src-tauri/tauri.conf.json` の値を使います。将来npmパッケージとしてのバージョンも管理する場合は、`package.json`も同じ値に揃えます。

### 3. ローカルでビルドを確認する

Apple SiliconのMacで、リリース対象のコミットを確認してから実行します。

```bash
bun install --frozen-lockfile
bunx tauri build --bundles dmg
```

sidecarのダウンロードやSwift helperのビルドも、この処理の一部として実行されます。初回は時間がかかることがあります。

## GitHub画面からリリースする

1. GitHubリポジトリの `Releases` を開く
2. `Draft a new release` を押す
3. `Choose a tag` に、バージョンを `v0.2.0` のように入力する
4. `Create new tag on publish` を選択する
5. 対象ブランチまたはコミットが、リリースしたい変更を指していることを確認する
6. Release titleを入力する（例: `Video Lecture to Notes v0.2.0`）
7. リリースノートを書く
8. `Publish release` を押す

タグの `v` を除いた部分は、`src-tauri/tauri.conf.json` のバージョンと一致させます。

```text
Release tag:              v0.2.0
tauri.conf.json version:  0.2.0
```

## Publish後に起きること

ReleaseをPublishすると、`release.published`イベントでGitHub Actionsが起動します。

Workflowは次の処理を行います。

1. Publishされたタグのソースをcheckoutする
2. GitHub runnerがApple Siliconか確認する
3. ReleaseタグとTauriバージョンが一致するか確認する
4. BunとRustの依存関係をインストールする
5. `bun run build`を実行する
6. 不足しているsidecarを準備する
7. TauriでmacOS用DMGを作成する
8. Publish済みのGitHub ReleaseへDMGをアップロードする

Actionsの実行状況は、リポジトリの `Actions > Build macOS release assets` から確認できます。

Workflowでは、sidecarとCargo依存ライブラリをGitHub Actions Cacheに保存します。Rustのビルド成果物全体である `src-tauri/target` はサイズが大きくなりやすいため、キャッシュ対象にはしていません。

sidecar準備中は、ダウンロード開始、HTTP応答、ダウンロード中の経過時間、SHA-256検証、展開のログが表示されます。ダウンロードが10分間完了しない場合はタイムアウトしてJobが失敗します。

## 配布物

成功すると、GitHub ReleaseのAssetsにmacOS Apple Silicon用のDMGが追加されます。

利用者には、ReleaseページからDMGをダウンロードして、アプリをApplicationsへコピーしてもらいます。

現時点ではApple Developer Programの証明書とnotarizationを設定していないため、初回起動時にmacOSのセキュリティ警告が出ます。

### 署名なしアプリを起動する方法

自分でビルドしたもの、または信頼できるGitHub Releaseからダウンロードしたものに限り、次のコマンドでダウンロード時の隔離属性を外せます。

```bash
xattr -dr com.apple.quarantine "/Applications/videolecture2notes.app"
open "/Applications/videolecture2notes.app"
```

Applicationsへコピーする前であれば、実際の `.app` のパスに置き換えて実行します。Finderでアプリを右クリックして `開く` を選ぶと起動できる場合もあります。

この対応は、Appleのコード署名やnotarizationの代わりになるものではありません。一般ユーザーへ配布する場合は、Developer ID署名とnotarizationを設定してください。

### バージョン更新時の注意

現在はアプリ内Updaterを実装していないため、各バージョンでDMGをダウンロードし、新しいアプリをApplicationsへコピーします。新しくダウンロードしたアプリには再び隔離属性が付くため、macOSの警告が出た場合は、基本的に更新のたびに次のコマンドを実行します。

```bash
xattr -dr com.apple.quarantine "/Applications/videolecture2notes.app"
```

Apple署名・notarization済みの配布物では、この手作業は不要です。将来Tauri Updaterを追加した場合はアプリ内から更新できるようになりますが、Apple署名・notarizationなしの状態では、OSの警告が出ないことまでは保証できません。

## 失敗した場合

### バージョン不一致

次のようなエラーの場合は、タグと `src-tauri/tauri.conf.json` のバージョンが一致していません。

```text
Release tag (v0.2.0) does not match src-tauri/tauri.conf.json (0.1.0).
```

誤ったタグをPublishした場合は、そのReleaseを削除して、正しいバージョンで作り直します。公開済みタグを使い回さず、修正したバージョン番号で新しいReleaseを作成してください。

### Apple Silicon以外のrunner

次のエラーの場合は、WorkflowのrunnerがIntelになっています。

```text
This project currently supports macOS Apple Silicon only.
```

このプロジェクトのsidecar準備処理自体がApple Silicon専用のため、Apple Silicon runnerを利用するか、先にIntel向けsidecar対応を追加します。

### sidecarのダウンロード・Swift helperのビルド失敗

Actionsのログで、失敗したsidecar名とSwift/Xcodeのエラーを確認します。外部配布元へのアクセス、SHA-256の不一致、runnerのmacOS SDKバージョンなどが原因になる可能性があります。

### DMGだけが足りない

Workflowを再実行します。Tauri Actionは同じReleaseに成果物をアップロードできます。既存Assetsがある場合は、同じ名前のAssetsを置き換えることがあります。

## 将来追加するもの

一般ユーザー向けに配布する段階では、次を追加します。

- `Developer ID Application`によるコード署名
- Apple notarization
- GitHub Actions Secretsへの署名情報登録
- Tauri Updater用の更新ファイルと署名鍵
- 起動時のアップデート確認UI

これらは、現在の「DMGをGitHub Releaseへ載せる」仕組みとは分離して追加できます。
